# Стрімінговий ASR → одночасний переклад (2026-10-31; фонетика 2026-11-01)

Друга перевірка whisper — rt-phonetic (символьна CTC-модель, на одиницю,
HTTP) з 2026-11-01, §8; початковий дизайн із Vosk-стрімом — у git-історії
цього файлу.

Власник: «Від початку я говорив, що whisper має працювати в режимі стрімінгу —
це значно пришвидшить обробку, Vosk теж має так само працювати, Qwen має
отримувати цю інформацію і розуміти контекст до і як далі перекласти.» Плюс:
«Коли натискається Start Translation — все має прогріватись.»

Протокол уже описаний у
[`2026-10-06-speech-services-api-design.md`](2026-10-06-speech-services-api-design.md)
§6.2–6.4; LocalAgreement-2 там був «P2, на майбутнє» — тут він основний.
Наявний каркас: `ws_routers` (`src/services/common/app.py`), `ws_authorized`
(`src/services/common/auth.py`), `Priority.FINAL/PARTIAL`
(`src/services/common/worker.py`), `websockets` у `nix/packages/deps.nix` і
`edge-deps.nix`.

## Рішення власника (дефолти, прийняті 2026-10-31)

1. Одиниця перекладу: кінець речення / endpoint (тиша) / ≥ 12 неперекладених
   слів на межі клаузи (`,;:`) / жорстко 20 слів.
2. Незафіксований хвіст показується в UI сірим, не озвучується.
3. Вже озвучений переклад не виправляється.
4. Режим transcribe теж переходить на стрім; паузний сегментатор видаляється.
5. `auto`-мова: визначається на першій репліці й фіксується на сесію.
6. Whisper turbo `int8_float16`, тік 500 мс, endpoint 500 мс тиші (800 мс
   спробувано 2026-11-01 і відкинуто: +1 с p50 / +2.5 с p90 замість прийнятих
   ~0.3 с, живі випадки не виправило — live test §18; короткі шматки
   об'єднує edge, §4).
7. Без пріоритету GPU між whisper і LLM (тіки latest-wins самі пригальмовуються).

## 1. Whisper — LocalAgreement-2

`StreamSession` (`src/services/asr/stream.py`, чистий клас): Silero VAD з
faster-whisper; кожні `RT_ASR_STREAM_TICK_MS` (500) перекодує буфер мовлення,
що росте (`beam_size=1`, `temperature=0` без fallback, `word_timestamps=True`,
`condition_on_previous_text=False`, `initial_prompt` = зафіксований текст
≤ 200 символів). Фіксує найдовший спільний префікс двох останніх гіпотез
(нормалізовані слова, пунктуація з новішої). Буфер обрізається по кінцю
зафіксованого речення, при > 15 с — по кінцю сегмента. VAD-тиша ≥ 500 мс
(endpoint) фіксує всю гіпотезу. `SegmentFilter`/`filter_repetitions` — на
кожну гіпотезу; перевірка echo-повтору prompt — на сервері. SimulStreaming
відкинуто: потребує cross-attention (немає в CTranslate2 → torch-whisper,
+~3 ГБ VRAM, немає в nixpkgs). Оцінка: 150–250 мс на тік turbo; тіки
latest-wins (пропуск, поки попередній рахується). Затримка фіксації ≈ 1.0–1.5 с
посеред мови, ≈ 0.7 с на паузі.

## 2. Друга перевірка — rt-phonetic на одиницю

Не стрім: на кожну вирізану одиницю [t0, t1] edge бере її аудіо з кільця
стріму rt-asr (`stream.audio(t0, t1)`) і шле в rt-phonetic одним HTTP-запитом
(§8). Час слів відповіді — від початку надісланого аудіо, edge додає t0.

## 3. Протокол `WS /v1/audio/stream` (rt-asr)

Клієнт: `start{language, sample_rate:16000, prompt?, t0}`, binary PCM16LE по
100 мс, `stop`. Сервер: `ready{session_id, model}`, `final{seq, text, words,
start, end, eos}` (лише дописується), `partial{text, start}` (замінює хвіст),
`endpoint{at}`, `error{code, state}`, `done`; кожне
несе `audio_end`.
Токен у handshake (невірний → close 1008); модель не готова →
`error{model_not_ready}` + 1013 (лінивий load як `runtime.acquire`); відкрита
сесія блокує idle unload; unload/RELOAD → `error model_unloaded` + 1012; ліміт
`RT_*_MAX_SESSIONS` → 1013. Edge: черга відправки ≤ 5 с аудіо, надісланого після
`ready` (беклог кільця до `ready` / повтор при перепідключенні — поза
лімітом), переповнення = обрив; failover через pool (`_mark_down`/`pick`) з
повтором кільцевого буфера від кінця останнього зафіксованого слова,
дублікати відкидаються за `end`; переповнення позначає endpoint down, лише
якщо є інший живий. Повтори (той самий endpoint / жодного) — з відступом
1 → 8 с, `failed` — раз на відмову (live test §15).
Рубильник: `stop` → `done` ≤ 1 с → close → `/model/unload`.

## 3a. Прогрів на «Start Translation»

Паралельно: обидва WS (handshake вантажить модель; вивантажена →
`POST /model/load` + чекати `ready`; сервер після `ready` робить фіктивний
декод 1 с тиші), прогрів LLM і TTS. Захоплення стартує одразу, аудіо — у
кільцевий буфер (≤ 30 с) до готовності WS і після `ready` надсилається
повністю (холодне завантаження 6–20 с не рве потік). UI: «прогрів…» з прапорцем на
кожен сервіс; тайм-аут/помилка видно явно. Лог: час від натискання до
повної готовності.

## 4. Edge — один механізм

`src/clients/stream.py` (WS-клієнт, потік, failover). `src/core/simul.py`:
`SourceLedger` (лише дописується) + `next_unit()` (правила з рішення 1;
крапка whisper остаточна, лише якщо за нею не йде мале слово без паузи, а
шматок з одного слова < 0.25 с приєднується до сусіда; ≤ 0.5 с очікування
наступного слова — live test §14; шматок на endpoint ≤ 3 слів без кінця
речення приєднується до наступної одиниці, якщо наступні слова вже є,
partial триває або < 1 с після endpoint — live test §18).
LLM: контекст — попередні пари source→target; user: `SOUND:` літери
фонетики (основа), `TEXT:` одиниця whisper, `NEXT (do not translate):` решта
зафіксованого + partial; NEXT — тільки для розуміння, продовжувати попередній
переклад узгоджено; `reject_reason` ловить витік NEXT і мета-відповіді.
Гейт фонетики — на одиницю (§8); відкинута одиниця лише зсуває ledger. TTS/відтворення без змін;
`_Phrase` → `_Unit`; без повторної озвучки (одиниці не перетинаються).

## 5. Бюджет, вимірювання, міграція

Зараз: кінець мови → звук p50 3.2 с, p90 9.3 с. Очікування (не виміряно):
p50 ≈ 2.5 с, p90 ≤ ~4 с. Вимірювати: `commit_lag`, мс/тік, пропущені тіки,
`behind_s`, рішення гейта фонетики, LLM/TTS first, кінець слова → звук
p50/p90, backlog відтворення, перепідключення, WER офлайн-повтором сесій.

Кроки (кожен — зелений повний набір тестів):
- **S1** rt-asr WS (`stream.py`, `ws.py`, налаштування, `/status.sessions`);
  перевірка — повтор WAV: фіксації проти HTTP-транскрипту, лаг.
- **S2** rt-vosk WS; перевірка — середня |Δt| збіжних слів < 150 мс.
- **S3** edge-клієнт, офлайн-стенд, прогрів.
- **S4** перемикання конвеєра + в тому ж коміті видалення: `_held*`,
  `_route_text`, `_release_held*`, `_flush_held`, `_hold_*`, `HOLD_POLL_S`,
  `_enqueue_segment`, `_recognize`, `_vosk_submit/_result`, `_is_echo`,
  лічильники `asr_merged`/`asr_held_flushed` (+ UI), `whisper_word_times`,
  `Aligned.build` (→ `from_words`), відповідні тести.
- **S5** transcribe на стрім; видалити `segmentation/pause.py`, `chunks.py`,
  `audio/vad_stream.py` (рівень сигналу — простий RMS), ключі `SegmenterConfig`.

HTTP `/v1/audio/transcriptions` rt-asr лишається для файлів і офлайн-оцінки; з
edge не викликається (edge кличе однойменний ендпоінт rt-phonetic, §8). Документацію (`docs/pipeline-diagrams.md`, `USAGE.md`)
оновлювати в кожному кроці.

## 8. Фонетика замість Vosk (2026-11-01)

Рішення власника 2026-11-01: Vosk прибрано повністю (сервіс, стрім, `idle`,
covers, очікування 300 мс, стан «не чує», перевірка мови стріму, HINT); на
його місці — `rt-phonetic` (порт 8092, discovery kind `phonetic`,
`services.use.phonetic` = auto / вузол / off), символьна wav2vec2 CTC-модель
`uk-wav2vec2-stress` без словника: пише літери, які чує. Докази —
[`context/phonetic-bench-2026-11-01.md`](../../../context/phonetic-bench-2026-11-01.md)
(CER 12 % проти 13 % whisper і 46 % Vosk на голосі власника, IT-слова 18/21
проти 5/21; гейт 0/39 хибних відкидань, 5/5 тиша порожня, 66/66 підмінених
фраз зловлено).

**Запит.** Одиниця → `POST /v1/audio/transcriptions` (wav 16 кГц її
відрізка, `language`), бюджет 0.5 с + 0.25 с на секунду аудіо одиниці,
1.5..4 с (`phonetic_budget_s`; фіксовані 1.5 с не встигали на 5/39 довгих
одиниць живого читання, напр. 10.2 с аудіо — live test §18; повтор сесії:
p50 0.29 с, p90 0.54 с, max 0.93 с), без failover усередині запиту (`EndpointPool.call_once`).
Тайм-аут / збій / 409 → лише whisper, лічильники `phonetic_timeout` /
`phonetic_unavailable` / `whisper_only`, WARN і подія в UI; 409
(`model_language_mismatch`, польська/російська) → «фонетика недоступна для
<мови>», ця мова більше не запитується.

**Гейт** (`core/crosscheck.py`): літери обох текстів (малі, без пробілів,
пунктуації, цифр), `difflib`-відношення; порожній транскрипт → `no_word`,
< 0.4 → `disagree` (відкинуто); латиниця whisper для uk-моделі — не доказ
(`foreign_terms`), < 4 літер whisper — без порівняння (`short_words`).

**Переклад — умова F.** SOUND (літери) — основне джерело, TEXT (whisper) —
лише правопис, межі слів, числа; де розходяться — SOUND. Як підказка до
whisper SOUND не допомагав (впевнені помилки whisper виживали). Промпт
налаштовано повтором сесії (`scripts/replay_session.py`): перша редакція
змушувала Qwen3.5-4B транслітерувати SOUND латиницею. Нова причина
`meta` у `core/output_guard.py`; відкинута відповідь «зі звуком», з якої в TTS
нічого не пішло, перекладається один раз лише з whisper (`retry_whisper_only`),
інакше — звичайне відхилення (`rejected_after_tts`).

**Видимість.** Вкладка «Фонетика» (модель, мова, load/unload), рядок
«Фонетика (rt-phonetic)» у панелі, «Звук: …» під фразою
(`ui.show_phonetic_text`), запис сесії з `phonetic`, `phonetic_words`,
`similarity`, `gate`, `mode` (sound | whisper-only | retry). Старі ключі
`config.yml` (`services.use.vosk`, `services.local.vosk`,
`services.llm.check_*`, `ui.show_vosk_text`, `{{vosk_text}}`) — явна помилка
з назвою нового ключа.

## 9. Наздоганяння черги відтворення (2026-11-01)

Англійська озвучка одиниці часто довша за українське мовлення: на 290-слівному
тексті кінець мови → початок відтворення p50 5.5 с, p90 9.9 с, max 14 с при
«звук готовий» p50 3.8 с (live test §18). Власник: «я повільніше говорю ніж
кокоро озвучує» — загалом не пришвидшувати; лише поки є черга.

`core/catchup.py` (`CatchUp`), стадія TTS перед кожною частиною: черга
(неозвучене + те, що грає) > 4 с → увімкнено; швидкість = `tts.speed` (не
задано — 1.0) × множник, що росте на 0.05 за частину до цілі за довжиною
черги (лінійно ×1.05 при 2 с … ×1.25 при ≥ 8 с), знижується одразу; < 2 с →
вимкнено, знову `tts.speed`. Кожна зміна — INFO `tts catch-up on/speed/off`;
`get_stats()["tts_catchup"]` = `active`, `factor`, `episodes`, `pieces`;
панель «Сервіси»: «черга відтворення N с: озвучка ×1.15». Сервіс rt-tts не
змінювався (поле `speed` запиту вже було).
